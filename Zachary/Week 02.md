Two slide decks: computational thinking, then top-down and bottom-up problem solving. Tutor on the slides: Syed Murad.

## Know this

Computational thinking is a way of approaching a complicated problem so you can describe a solution. The slides tie it to logical thinking and critical thinking: formulate the problem, then express the solution.

Four techniques:

- **Decomposition.** Break the problem into smaller parts and solve the parts. The running example is "survive", split into food, water, shelter and rescue, then split again (fishing, cook, source, purify, and so on).
- **Pattern recognition.**
- **Abstraction.**
- **Algorithmic thinking.**

**Top-down.** Start with the whole problem and keep breaking it into smaller programs. If a subprogram is still too hard, break that too. The slides say this is mainly used by structured languages such as C, Fortran and COBOL. You start at the most abstract description and add detail, like an outline that becomes a story. Advantages listed on the slide: a clear overview, simpler problems, better organisation, easier communication in a team, more control, reusable components, resource allocation, and easier maintenance.

**Bottom-up.** Build the small pieces first, then join them into the whole program. The slides say this is mainly used by object-oriented languages such as C++, Python and C#.

**Modularisation.** Breaking a program into packages. The slides say those packages can be called methods, functions, subroutines or procedures.

The learning outcome also says you should know the disadvantages of each approach. The exported text lists advantages of top-down only. It does not list disadvantages.
